# Продуктовый словарь и рабочие артефакты

Используй только разделы, необходимые для текущего решения. Шаблоны — заготовки, не повод заполнять неизвестное выдуманными данными.

## Вокабуляр

| Термин | Рабочее значение |
| --- | --- |
| Problem space / solution space | Потребности и препятствия / варианты их решения. Не перескакивай ко второму без первого. |
| Discovery / delivery | Снижение неопределённости ценности и решения / создание и поставка решения. |
| JTBD | Прогресс, которого человек пытается достичь в определённой ситуации; не название функции. |
| ICP / segment | Профиль наиболее подходящего клиента / группа с общими значимыми потребностями и поведением. |
| Value proposition | Для кого, какую ценность и в сравнении с какой альтернативой создаём. |
| Opportunity | Возможность повлиять на outcome через потребность, боль или желаемый прогресс. |
| Outcome / output / impact | Изменение поведения или результата / поставленный артефакт / более широкий эффект для бизнеса или людей. |
| North Star Metric / input metrics | Показатель устойчиво доставляемой ценности / управляемые факторы, влияющие на него. Не назначай NSM механически. |
| Activation / retention / churn | Достижение первой значимой ценности / возвращение или сохранение активности / отток. Всегда уточняй событие, cohort и период. |
| Leading / lagging indicators | Ранние сигналы / наблюдаемые итоговые результаты. Связь между ними требует проверки. |
| Guardrail | Ограничитель: что нельзя ухудшать ради основной метрики. |
| MVP / MLP | Минимальная проверка ценности / акцент на минимально привлекательном опыте. Термин не заменяет явный scope. |
| RICE | Reach, Impact, Confidence, Effort. Рейтинг помогает обсуждать выбор, а не доказывает его объективность. |
| Opportunity cost / cost of delay | Ценность упущенной альтернативы / последствия откладывания решения. |
| Unit economics | Доходы и затраты на согласованную единицу; определяй contribution margin и включённые затраты. |
| LTV / CAC / payback | Ценность клиента за период отношений / стоимость привлечения / срок окупаемости. Определения, cohort и база расчёта должны совпадать. |
| Pricing / packaging / GTM | Цена / состав предложения и тарифов / способ выхода к выбранному рынку и покупателю. |
| Roadmap / backlog | Последовательность намерений и outcomes / упорядоченная работа. Roadmap не является обещанием всех дат. |
| Product-market fit | Устойчивое соответствие продукта спросу выбранного рынка; одна метрика сама по себе его не доказывает. |

## Decision brief / компактный PRD

```text
Инициатива / версия / статус / decision owner:
Решение, которое требуется:
Рекомендация и основание:
Сегмент, пользователь, покупатель:
Проблема / JTBD / текущая альтернатива:
Evidence: источник, дата, наблюдение, ограничение:
Допущения и что их опровергнет:
Outcome / metric definition / baseline / proposed target / horizon:
Guardrails:
Варианты: no change / минимальный / расширенный; trade-offs:
MVP и ключевой сквозной сценарий:
In scope / out of scope:
Зависимости, ограничения и оценки с владельцами:
Rollout / rollback / support readiness:
Открытые решения: вопрос, влияние, предлагаемый владелец:
Следующий шаг и критерий завершения:
```

## Карточка эксперимента

```text
HYP-ID / гипотеза / сегмент / механизм:
Самое рискованное допущение:
Метод и почему он подходит:
Единица наблюдения; для A/B — единица рандомизации:
Primary metric / baseline / минимально значимый эффект:
Выборка: доступные данные, расчёт или недостающие входы:
Окно наблюдения / бюджет / guardrails / stop criteria:
Решение при успехе / провале / неубедительном результате:
Риски смещения и ограничения причинного вывода:
Результат: planned / running / completed; evidence:
```

## Передача БА и архитектору

Передай initiative ID, problem statement, сегмент, цель и metric definition, evidence, продуктовые решения, in/out of scope, ключевые сценарии, ограничения и открытые вопросы. Получи обратно найденные пробелы, конфликтующие правила, зависимости, варианты стоимости и влияния на scope. Изменение scope фиксируй новой версией решения, не тихой правкой.

Рабочий цикл: `PM: intention → BA: specification → architect: feasibility → PM: scope trade-off`. Это маршрут ответственности, не требование автоматически запускать агентов. При споре зафиксируй позиции и недостающие доказательства; передай решение уполномоченному владельцу, не имитируй консенсус.

## Синтетический пример

Запрос: «Добавим AI-чат в сервис».

Плохой результат: перечень экранов чата и выдуманный рост retention на 20%.

Хороший результат: «Сначала установим сегмент и задачу, на которой пользователи теряют время. Гипотеза: помощь внутри текущего сценария сокращает время до первого успешного результата. Baseline не измерен. Сравним текущий сценарий, улучшенные подсказки и concierge-помощь; предложим пилот с измерением completion rate, time-to-value, стоимости успешного кейса и числа ошибок. Продуктовый scope выбираем по результату, а не по привлекательности технологии».
