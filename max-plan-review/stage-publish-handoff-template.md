## Commit-hooks

Прочитать фактические hooks и wrapper-команды. Для каждого выбрать `выполнить`, `пропустить штатным --no-verify` или `штатный пропуск не поддерживается`; общий вывод без построчного сопоставления проверок недопустим. Полностью покрытый bypass-capable hook обязательно пропустить, частично покрытый — выполнить.

| Hook или wrapper | Поддерживает штатный пропуск | Выполняемые проверки/изменения | Уже закрывающий evidence | Совпадает snapshot/message/state | Решение | Команда |
|---|---|---|---|---|---|---|
| `pre-commit` | да | ... | ... | да / нет | выполнить / пропустить | `git commit ...` / `git commit --no-verify ...` |
| `prepare-commit-msg` | нет | ... | ... | ... | выполнить | штатная commit-команда |
| `commit-msg` | да | ... | ... | да / нет | выполнить / пропустить | ... |
| `post-commit` | нет | ... | ... | ... | выполнить | штатная commit-команда |

Если хотя бы одна проверка hook не покрыта на точном snapshot, выполнить hook. Mutating-hook можно пропустить только после эквивалентного преобразования и повторной проверки принятого дерева.

Перед `git commit --no-verify` подтвердить полное покрытие обоих hooks, которые он обходит: `pre-commit` и `commit-msg`. Если один из них не покрыт, получить для него точное evidence отдельно либо выполнить commit без `--no-verify`.
