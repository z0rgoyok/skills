# Read-only research через Luna

Читать этот файл перед отделимым исследованием репозитория, истории, GitLab/Jira/Confluence, внешней документации или интернета.

## Когда делегировать

Макс обязан вызвать Luna, если для решения нужно собрать или сопоставить evidence из нескольких файлов, коммитов, jobs/pipelines, задач, страниц либо внешних источников. Типичные задачи: восстановить историю изменения, классифицировать отказ CI, найти действующий внешний контракт, проверить документацию зависимости, сравнить реализации и найти существующую точку переиспользования.

Не создавать агента ради одного `git status`, hash, точного локального файла или уже известной строки. Фактический staged diff и фазовый verdict Макс всегда проверяет сам; Luna может собрать только вспомогательное evidence.

## Запустить одного исследователя

Использовать `collaboration.spawn_agent`:

- model: `gpt-5.6-luna`;
- reasoning effort: `xhigh`;
- `fork_turns: none`;
- один узкий `task_name` по предмету исследования.

Эквивалентный вызов:

```text
spawn_agent(
  task_name: "research_<scope>",
  fork_turns: "none",
  model: "gpt-5.6-luna",
  reasoning_effort: "xhigh",
  message: <полный research-пакет>,
)
```

В поручении явно запретить вложенных субагентов. Связанные вопросы объединять в один research-пакет; не создавать несколько агентов для одного решения.

После запуска не повторять порученный поиск на Sol. Макс может упорядочить уже известные факты и критерии решения, затем ждёт результат через `wait_agent` с длинным ожиданием.

## Передать полный research-пакет

Поручение должно быть самодостаточным и содержать:

1. Роль: read-only исследователь, не Макс и не владелец решения.
2. Решение Макса, для которого собирается evidence, и один точный вопрос исследования.
3. Repository/cwd, branch, `HEAD`, текущую фазу и значимое состояние дерева.
4. Подтверждённый контекст, применимые ограничения и явный out-of-scope.
5. Точные пути, URL, task/MR/pipeline/job/commit ID и приоритет источников, если они известны.
6. Какие факты нужно подтвердить, какие альтернативы сравнить и какие противоречия искать.
7. Требование отделять факт, вывод и неизвестное; для каждого факта приводить точный source path/line, URL, SHA, job ID или короткий релевантный фрагмент evidence.
8. Формат результата: краткий вывод, таблица evidence, противоречия, неизвестные и точные вопросы Максу.

Для Fix Price передать путь к обязательному `$fp` и только применимые проектные навыки. Для технического интернет-поиска потребовать первичные источники: официальную документацию, спецификацию или исходный репозиторий. Не просить Luna самостоятельно восстанавливать контекст из истории чата.

Использовать такой каркас поручения, заполняя все поля фактическими данными:

```text
Ты read-only Luna-исследователь. Ты не Макс, не принимаешь решений и не запускаешь субагентов.

Решение Макса, для которого нужно evidence: <решение>.
Точный вопрос: <один вопрос>.
Контекст: repository <path>, branch <branch>, HEAD <sha>, phase <phase>, tree state <state>.
Подтверждённые факты: <факты>.
Источники по приоритету: <paths/URLs/IDs>.
Нужно установить: <список фактов и сравниваемых альтернатив>.
Вне scope: <границы>.

Работай абсолютно read-only: не изменяй файлы, plan/handoff, Git state или внешние системы;
не запускай команды с побочными записями и не скачивай ничего в workspace.

Верни: краткий ответ; таблицу «факт — evidence — точный источник»;
противоречия; неизвестные; точные вопросы Максу. Отделяй выводы от фактов.
```

## Сохранить абсолютный read-only режим

Luna запрещено:

- создавать, изменять, удалять, форматировать или генерировать любые файлы, включая plan/handoff и временные файлы в workspace;
- использовать `apply_patch`, перенаправление вывода в файл или команды, создающие build/generated/cache artifacts в проекте;
- выполнять `git add`, commit, push, fetch, pull, merge, rebase, reset, checkout, switch, clean, stash, tag или менять refs/index/worktree;
- скачивать артефакты в workspace, устанавливать зависимости либо запускать тесты и генераторы, меняющие дерево или кеши проекта;
- перезапускать, отменять или создавать CI jobs/pipelines, писать комментарии, менять Jira/Confluence/GitLab/GitHub и выполнять другие внешние мутации;
- принимать продуктовые или архитектурные решения, менять фазу, писать plan/handoff/findings/verdict;
- запускать вложенных субагентов.

Разрешены только чтение файлов и уже существующих артефактов, read-only Git-команды, GET/read-only API, просмотр логов и интернет-источников. Если инструмент нельзя уверенно считать read-only, не использовать его и вернуть Максу точный пробел evidence.

## Уточнять у того же агента

Макс проверяет, отвечает ли результат на исходный вопрос и содержит ли проверяемые ссылки. Если evidence неполно или противоречиво, использовать `collaboration.followup_task` для того же агента, передать только недостающий вопрос, найденное противоречие и требуемый формат дополнения, затем снова ждать через `wait_agent`. Не запускать нового исследователя и не повторять уже собранное.

Продолжать уточнения до decision-ready evidence либо явной недоступности источника. При недоступности назвать пробел и его влияние на решение; не заполнять его предположением.

## Принять результат Максом

Luna возвращает evidence, а Макс лично:

- проверяет одну критичную ссылку или первичный источник, если вывод меняет публичный контракт, безопасность, данные или фазу;
- отделяет подтверждённые факты от вывода исследователя;
- принимает архитектурное и фазовое решение;
- пишет plan/handoff и сохраняет необходимые изменения.

Не повторять весь research на дорогой модели. Точечная проверка критичного evidence достаточна.
