# Локальный запуск Slopo

## Когда читать

Прочитать перед первым запуском аудита в репозитории, при смене версии, модели, языка, области или порогов, а также при ошибке индекса.

## Закреплённый профиль

По умолчанию навык использует проверенный профиль:

- Slopo `0.5.1`;
- модель `ollama/unclemusclez/jina-embeddings-v2-base-code`;
- размер embedding `768`;
- основной порог similarity/rerank `0.92/0.94`;
- мягкий порог `0.88/0.92`;
- минимальное тело функции `10` AST-узлов.

Менять профиль можно для отдельного измеримого эксперимента. Новую модель, размер embedding или `body_node_count_threshold` индексировать в новом временном каталоге. Результаты разных профилей не объединять в одну базовую линию.

Slopo `0.5.1` поддерживает Python, TypeScript, JavaScript, Java, Kotlin, C#, Go, Rust, PHP и Elixir. Vue SFC, Dart, SQL, shell и Markdown этим профилем не покрываются. Перед выводом о всём проекте посчитать поддерживаемые и неподдерживаемые файлы через `git ls-files`.

## Предварительные условия

Требуются `git`, `uv`, `curl`, Ollama и не менее 500 МБ свободного места. Проверить:

```shell
git rev-parse --show-toplevel
git rev-parse HEAD
git status --short
uv --version
ollama --version
curl --silent --show-error --fail http://127.0.0.1:11434/api/tags >/dev/null
uvx --from slopo==0.5.1 slopo --version
```

Если API Ollama недоступен, запустить `ollama serve` в отдельном терминале. Если модели нет, загрузить её:

```shell
ollama pull unclemusclez/jina-embeddings-v2-base-code
ollama show unclemusclez/jina-embeddings-v2-base-code
```

Зафиксировать показанный идентификатор модели. Один и тот же тег может со временем указывать на другой образ.

## Выбор области

Перед запуском посмотреть состав файлов и выбрать один связный source root. Не передавать корень диска, домашний каталог или весь монорепозиторий без проверки состава.

Типичные исключения:

- `.git/**`, `vendor/**`, `node_modules/**`, `.venv/**`;
- `dist/**`, `build/**`, `coverage/**`, временные и кэш-каталоги;
- сгенерированные клиенты, ORM и protobuf;
- `**/*.min.js` и собранные bundles;
- `**/*_test.go`, `**/*.test.ts`, `**/*.spec.ts`, fixtures и testkit для отдельного production-аудита.

Не копировать этот список механически. Сначала сверить реальные пути проекта. Если тестовая инфраструктура сама является предметом аудита, выполнить второй прогон со своей областью и не смешивать его числа с production-кодом.

## Запуск

Скрипт создаёт приватный временный каталог, две конфигурации, одну SQLite-БД и основной с мягким отчёты:

```shell
~/.codex/skills/semantic-duplication-audit/scripts/run_slopo_audit.sh \
  --source /absolute/path/to/source \
  --exclude 'vendor/**' \
  --exclude '**/*_test.go' \
  --exclude 'generated/**'
```

Полезные параметры:

```text
--source PATH                 обязательная область анализа
--exclude GLOB               повторяемое gitignore-подобное исключение
--similarity VALUE           основной similarity, по умолчанию 0.92
--rerank VALUE               основной rerank, по умолчанию 0.94
--loose-similarity VALUE     мягкий similarity, по умолчанию 0.88
--loose-rerank VALUE         мягкий rerank, по умолчанию 0.92
--body-node-count INTEGER    минимум AST-узлов, по умолчанию 10
--slopo-version VERSION      по умолчанию 0.5.1
--model MODEL                LiteLLM-имя модели
--dimensions INTEGER         размер embedding, по умолчанию 768
--skip-loose                 не создавать мягкий отчёт
```

Скрипт завершает работу строкой `ANALYSIS_ROOT=...`. Внутри находятся:

- `run-metadata.txt` с параметрами и Git-состоянием;
- `config.yaml` и `config-loose.yaml`;
- `slopo.db` с индексом и embedding;
- `report/index.md` и файлы основных кластеров;
- `report-loose/index.md` и файлы мягких кластеров.

Основной отчёт даёт наиболее уверенные совпадения. Мягкий повышает полноту и стоимость ручного разбора. Если мягкий отчёт слишком велик, не снижать порог бесконечно: выбрать измеримый шаг и зафиксировать, какая часть просмотрена.

Для проекта, который будут проверять повторно, не копировать временные конфигурации вручную. Использовать [постоянный профиль проекта](project-setup.md): он сохраняет область и исключения, переиспользует индекс и отделяет коммитируемые файлы от локальных артефактов.

## Значение метрик

- `Exact copies`: единицы с одинаковым телом. Несколько единиц могут описывать один случай.
- `Similarity ratio excluding exact copies`: доля неточных совпадений среди единиц после исключения точных копий. Это не процент продублированных строк.
- `Score`: близость с поправкой Slopo на расстояние по файлам или строкам; после boost значение может быть выше `1.0`.
- `Cluster`: группа кандидатов. Номер не означает критичность и может измениться при другом профиле или составе файлов.

## Восстановление

| Признак | Проверка и действие |
|---|---|
| Ollama недоступен | Запустить `ollama serve`, проверить `/api/tags`, повторить незавершённую команду |
| Модель отсутствует | Выполнить `ollama pull`, проверить идентификатор |
| Индекс содержит 0 единиц | Проверить `--source`, исключения, расширения и поддержку языка |
| Slopo отклоняет существующую БД | Создать новый прогон после смены source, модели, dimensions или body threshold |
| В отчёте только boilerplate | Сузить область или добавить подтверждённые исключения и создать новый индекс |
| Мягкий отчёт слишком большой | Вернуться к основному либо повысить пороги; записать просмотренную границу |

## Очистка

Сначала сохранить итог. Затем проверить точный путь из `ANALYSIS_ROOT` и удалить только этот каталог. Не использовать неразрешённые переменные, домашний каталог, корень репозитория или широкий glob как цель удаления.
