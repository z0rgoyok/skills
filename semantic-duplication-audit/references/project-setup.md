# Постоянный профиль проекта

## Когда читать

Прочитать, если пользователь просит подключить проект, сохранить настройки аудита или упростить следующие запуски. Этот режим изменяет репозиторий. Для обычного запроса «проверь дублирование» использовать временный read-only запуск.

## Устройство контура

Для каждой связной области создаётся отдельный профиль:

```text
.slopo/
|-- backend.yaml              основной профиль, можно коммитить
|-- backend-loose.yaml        мягкий профиль, можно коммитить
|-- backend.ignore.txt        проверенные hash кластеров, можно коммитить
`-- local/                    БД, отчёты и метаданные запуска, всегда игнорировать
```

Профили разделять по приложению, языку и назначению. Примеры: `backend-go`, `web-typescript`, `tests-go`. Не смешивать production-код и тесты в одном профиле.

Конфигурация не должна содержать API-ключей и абсолютных пользовательских путей. Все пути записываются относительно корня репозитория, а запуск выполняется из корня.

## Создание профиля

Сначала проверить состав source root и подобрать исключения. Затем выполнить:

```shell
~/.codex/skills/semantic-duplication-audit/scripts/setup_project_profile.sh \
  --project-root /absolute/path/to/repository \
  --profile backend-go \
  --source apps/backend \
  --exclude 'vendor/**' \
  --exclude '**/*_test.go' \
  --exclude 'generated/**'
```

Скрипт:

- создаёт основной и мягкий YAML-профили;
- создаёт пустой `<profile>.ignore.txt`, не затирая уже просмотренные hash;
- добавляет `.slopo/local/` в корневой `.gitignore`;
- отказывается перезаписывать существующие профили без `--replace`;
- не запускает Ollama, не загружает модель и не анализирует код.

После создания обязательно проверить `git diff`. Если репозиторий использует другую структуру служебных файлов или локальных исключений, адаптировать профиль к его правилам до первого запуска.

## Первый и повторный запуск

```shell
~/.codex/skills/semantic-duplication-audit/scripts/run_project_profile.sh \
  --project-root /absolute/path/to/repository \
  --profile backend-go
```

Команда выполняет `show-config`, инкрементальные `index` и `embed`, затем создаёт основной и мягкий отчёты. Повторный запуск обрабатывает изменившиеся единицы и сохраняет результаты в `.slopo/local/`.

После ручного разбора отклонённые hash можно добавить в `.slopo/<profile>.ignore.txt` и закоммитить. Не добавлять hash подтверждённых кандидатов до завершения решения: иначе они исчезнут из следующего отчёта. После изменения кода кластер с новым hash появится снова.

## Обновление профиля

При осознанном изменении области, исключений или порогов повторить setup с `--replace`, затем проверить diff. Смена `source_dir`, модели, dimensions или `body_node_count_threshold` несовместима с прежней БД: удалить только `.slopo/local/<profile>.db` и связанные отчёты либо создать новый профиль с другим именем.

Не добавлять команду в `Makefile`, `Taskfile`, CI или package scripts автоматически. Интегрировать её в штатный task runner только по отдельной просьбе и после проверки правил проекта. Аудит не должен становиться блокирующим quality gate без собственной базовой линии и согласованной стоимости ручного разбора.
